# 음악 맞추기 게임

현장 진행자가 사용하는 15문제 음악 맞히기 웹앱. 하늘색과 시스템 글꼴을 사용한 Finder 스타일 UI이며 참가자, 점수, 정답, 순위, 승자 데이터는 관리하지 않습니다.

- 앱: https://sioninzion.github.io/pastel-music-finder/
- 소스: https://github.com/sioninzion/pastel-music-finder

## 먼저 준비할 것

**사용자가 제공한 실제 MP3 15개가 저장소에 포함되어 있으며, 접속 시 자동으로 준비됩니다.** YouTube 링크는 제목 확인용입니다. 다운로드·이용 허락이 확인되지 않은 콘텐츠를 추출하지 않습니다. 사용할 권한을 확보한 15곡을 직접 준비하세요. 준비 화면 → 시작 → 게임 방법 → 15개 문제 선택 순서로 진행합니다. 화면에는 곡명 대신 번호만 표시됩니다. 정적 앱이므로 소스나 개발자 도구에서 메타데이터를 비밀로 보호하는 구조는 아닙니다.

1. 아래 고정 번호와 `public/tracks.json`을 확인합니다.
2. `01 - Whiplash.mp3`처럼 **번호 - 제목**으로 파일을 준비합니다. 실제 확장자를 유지하세요. 로컬 연결은 MP3, WAV, M4A 등 브라우저가 디코딩할 수 있는 오디오를 지원합니다.
3. 앱의 **음원 파일 선택**에서 15개 파일을 한꺼번에 선택합니다. 파일명 앞의 번호로 연결하며 서버로 업로드하지 않습니다.
4. 15곡 모두 디코딩·저장이 완료되어야 문제를 재생할 수 있습니다. 준비 중에도 시작·설명·파일 목록을 볼 수 있지만 문제는 비활성입니다. 손상되었거나 5초 미만인 파일은 거부합니다.
5. `오프라인 준비 완료`를 확인한 후 인터넷을 끄고 **같은 브라우저·같은 주소**를 새로고침해 실제 음원을 테스트합니다. 브라우저가 저장 공간을 지우면 다시 연결해야 합니다. 시크릿 모드를 피하세요.

로컬 파일 연결은 공개 인터넷 배포 권한이 없는 파일을 저장소에 올리지 않아도 사용할 수 있게 합니다. 현장 재생에 필요한 이용 허락은 별도로 확보해야 합니다.

## 기술 구성

React 19, TypeScript, Vite 8, Web Audio API, Cache Storage, Service Worker, localStorage. 서버·DB·로그인 없음. URL 해시와 브라우저 history를 사용하며 GitHub Pages 하위 경로를 지원합니다. 폰트는 운영체제 기본 산세리프를 사용합니다. Apple 글꼴 파일은 포함하지 않습니다.

`src/audio.ts`는 AudioBufferSource의 오디오 시계에 시작 시각과 재생 구간 길이를 예약합니다. JS setTimeout에 의존해 클립을 자르지 않습니다. 클릭마다 기존 소스·예약을 중단하고 비동기 디코딩에도 세대 번호를 적용해 오래된 요청이 재생되지 않도록 합니다. 0.8초 준비 후 재생하되 느린 디코딩이 0.8초를 넘으면 준비가 끝난 뒤 시작합니다. 활성 음원 하나를 디코딩하며 준비 검사 시에는 순차 검사로 메모리 증가를 줄입니다.

## 실행·빌드

Node.js 24 권장.

```sh
npm ci
npm run dev
npm run build
npm run preview
npm test
```

기본 경로는 `/pastel-music-finder/`입니다. 개발 서버에 표시되는 이 경로로 접속하세요. 다른 저장소 이름은 `BASE_PATH=/다른이름/ npm run build`로 설정할 수 있습니다. Actions는 저장소 이름에서 base 경로를 자동 생성합니다. Windows PowerShell에서는 `$env:BASE_PATH='/다른이름/'; npm run build`를 사용합니다.

## 대표 구간 설정

`public/tracks.json`에서 해당 곡의 `highlightStart`만 수정합니다.

```json
{ "id": 1, "highlightStart": "1:23.5", "highlightDuration": 3 }
```

`83.5` 같은 숫자 또는 `"1:23.5"` 형식을 지원합니다. `null`이면 대표 버튼과 R 단축키는 비활성입니다. 3초 재생 길이는 고정됩니다. 음원 길이를 벗어난 구간은 오류를 표시하고 재생하지 않습니다. 설정 변경 후 빌드·push하세요. 서비스 워커 업데이트가 있으면 앱을 연 모든 탭을 닫았다가 다시 열어 최신 버전으로 전환합니다.

## 음원 변경·호스팅

기본 사용법은 브라우저에서 로컬 음원을 선택하는 방식입니다. 설정은 진행자용 톱니 아이콘에서 다시 열 수 있습니다. 파일명이 달라도 앞의 고정 번호가 맞으면 연결됩니다. 브라우저 캐시는 기기·프로필·사이트별로 독립적입니다.

온라인 사전 다운로드를 원하고 **공개 배포 권한까지 확보했다면**:

1. `public/tracks.json`의 `audioFile`과 동일한 파일명으로 `public/audio/`에 넣습니다.
2. 파일이 바뀌면 해당 `audioVersion`을 증가시킵니다. 같은 버전은 캐시를 재사용합니다.
3. 음원은 실수로 공개되지 않도록 `.gitignore`에 제외했습니다. 권한 확인 후 해당 파일만 `git add -f`로 명시적으로 추가합니다.
4. `npm run build`로 파일당 100 MiB 미만, 배포 합계 950 MiB 미만과 LFS pointer가 아닌지 검사합니다. 현재 MP3 15개의 합계는 약 96.54 MiB이고 최대 파일은 약 10.70 MiB입니다. 원본 음질과 파일 내용을 그대로 유지했습니다.

앱 시작 시 각 음원의 버전별 캐시를 우선 확인하고 없으면 배포 경로를 fetch합니다. 내려받은 파일을 디코딩 검증하고 Cache Storage에 저장합니다. 가져온 로컬 파일도 같은 버전별 키를 사용합니다. 변경된 버전만 새로 준비해야 합니다. 저장 용량 부족이나 브라우저 데이터 삭제 때는 자동으로 성공한 것처럼 처리하지 않습니다. OS가 저장 공간을 회수할 가능성은 있으므로 행사 당일 오프라인 검사가 필요합니다.

UI·JSON·JS·CSS는 빌드 해시별 서비스 워커에 캐시됩니다. 새 버전은 기존 탭이 모두 닫힌 후 활성화되어 게임 중 UI 버전이 바뀌지 않습니다. 음원은 앱이 직접 Blob으로 읽으므로 Range 요청 캐시 문제를 피합니다.

## 게임 진행

- 문제 파일 클릭 → 1 / 3 / 5 / 대표 / 전곡 파일 클릭.
- 1·3·5는 처음부터 지정 초, 대표는 지정 위치부터 3초, 전곡은 전체 재생.
- 키보드: `1`, `3`, `5`, `R`, `F`, `Space` 일시정지·재개, `Esc` Finder 복귀.
- 복귀하면 재생 여부와 무관하게 해당 문제 완료. 브라우저 뒤로 가기도 동일합니다.
- 완료된 문제는 계속 열 수 있습니다. 새로고침은 안전하게 Finder로 돌아가며 진행도는 유지됩니다.
- 15번째 완료 후 0.9초의 여유를 두고 GAME OVER → 3초 후 `과연 승자는?`.
- 하단 작은 초기화 아이콘 → 확인 대화상자에서 완료 표시만 초기화. 번호·음원·대표 구간은 유지.

## GitHub Pages 배포

저장소 Settings → Pages → Source를 **GitHub Actions**로 설정합니다. `main` push 시 `.github/workflows/pages.yml`이 npm ci → 빌드 → Pages 배포를 수행합니다. 현재 배포는 서버에 저장된 15곡을 자동 다운로드·검증하고 브라우저에 캐시합니다. 음원 교체 시 로컬 파일 선택도 사용할 수 있습니다.

`browser-tests.yml`은 Windows runner에서 실제 Chrome과 Edge 채널에 대해 E2E 검증을 수행합니다. 합성 WAV는 테스트 실행 중에만 메모리에서 생성되며 실제 음악으로 대체하거나 배포하지 않습니다.

## 검증

`npm test`는 로컬 설치된 Chrome을 사용합니다. 필요하면 `npx playwright install chrome`을 먼저 실행하세요. Windows 두 브라우저는 `$env:WINDOWS_BROWSERS='1'; npm test`로 실행합니다. 테스트는 준비 진입 제한, 손상 음원 거부, 오디오 시계 예약 값, 빠른 클릭, 일시정지·재개, 대표 위치·전곡 길이, 키보드, 뒤로가기, 완료·초기화·새로고침, 오프라인 새로고침·재생, 15문제 종료, 1366/1920/390 폭의 레이아웃을 확인합니다.

자동 테스트가 실제 행사 음원·스피커·Windows 오디오 드라이버의 청감 검증을 대신하지는 않습니다. 실제 음원이 제공되면 현장 장비에서 음량, 시작 무음, 대표 시점, 클리핑을 최종 확인해야 합니다.
